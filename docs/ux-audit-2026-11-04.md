# Untangle UX audit, 4 November 2026

Audit base: `76083e2`, branch `feat/ux-audit-polish`, PR base `feat/recorder-setup`. This is a source and synthetic UI audit of the Linux app. It is not a hardware acceptance test or a security certification.

The strongest existing choices are local saving, explicit playback, clear microphone state text, and distinct upload recovery states. The next investment should be trustworthy completion and recovery cues. Adding an editor or copying a competitor's cloud defaults is a separate product decision.

## Evidence and limits

Read AGENTS.md, TODO.md, UI standards and testing notes. Inspected recorder construction/state transitions, Settings, camera adjustments, audio check, floating controls, library/player, naming, Loom account/upload, Drive/archive/cleanup, shutdown and their supporting engine/audio/composition/storage boundaries. Reviewed test coverage for those paths. File/line references below refer to this PR's source; linked files are relative to this document.

Inspected existing actual Qt captures in `docs/settings-ui/recorder-light.png`, `settings-dark.png`, `library-light.png`, and `docs/naming-ui/error-dark.png`. These show synthetic pixels and establish the earlier visual hierarchy only. The old library image lacks Drive, retention and row actions now present in source. It must not be treated as a current visual baseline.

The only execution checks used were `./scripts/test.sh` and `bash -n scripts/*.sh bin/*`. The suite exercises production Qt widgets with synthetic boundaries in bubblewrap. No standalone renderer, normal app session, device capture, audible playback, speech service, authentication, upload, installation or deployment was run. This task's narrower check restriction overrides the UI standards' separate screenshot-regeneration command. Current changed pixels were not separately rendered. Live encoded pixels, desktop stacking, real microphone intelligibility, real service permissions and performance remain unverified.

The first runner invocation used system Python because the checkout lacked `.venv`; it failed with missing PySide6 and dependency-related errors. A temporary local symlink to the existing project `.venv` allowed the same runner to use installed dependencies, without installing packages. Final results are recorded below.

## Small polish implemented

These changes have negligible expected behavioral risk, not zero risk. Copy can still confuse people or wrap differently.

- [app.py](../src/untangle/app.py), lines 499 and 689–690: give the symbol-only window refresh control a descriptive accessible name, and identify the pointer zoom amount with a name and tooltip. These are widget metadata only; they do not enable a screen reader or change desktop accessibility settings.
- [recordings.py](../src/untangle/recordings.py), lines 115, 129–130 and 285: explain that review starts with Play, describe search as matching names/dates/formats, and clarify that Copy path copies a local filename rather than a share link. The filter already searches these fields at lines 369–375.

No signal wiring, persisted values, capture choices, audio processing, upload/auth/deletion policy or compatibility identifiers changed. No new test duplicates these static strings; existing Qt interaction/geometry checks exercise the affected widgets.
