# Recording projects and versioned exports

The first editor trims a recording into a new MP4. It never replaces the recording, uploads an export, or plays media automatically. Enter start and end times in seconds, then export. End `0` means the end of the recording. Exports are H.264 video and AAC audio where audio exists; encoding can reduce quality.

Each recording has an adjacent `<filename>.untangle-project` directory with `project.json` and numbered exports. Keep this directory for export history. Projects are bound to the original path and file identity; renaming or moving the recording starts a new project. Old exports remain readable in their old project folder. The project retains source identity, trim recipes, version outcomes and track roles. Existing OBS files have a composed video track and mixed audio track. Camera position, camera size and microphone balance are already baked into these files. They cannot be recovered as independent sources by the editor.

Schema version 1 records a source path and device/inode/size/mtime identity, source-backed track descriptors, and append-only version recipes. The track descriptors have `role`, `source` and `stream` fields and explicit `editable_layout: false`. A future capture format can add separate screen, camera and microphone source descriptors and a composition recipe in a new schema version. It must save all capture tracks before claiming layout editing is available. No capture or compatibility identifier migration is part of this editor.

A per-project file lock prevents simultaneous exports. The editor journals a pending numbered version before encoding to a temporary file, checks source identity again, and publishes the export without replacing any existing version. It then atomically saves the completed recipe. Failed and cancelled attempts keep their version numbers; retries create new numbers. A crash leaves a pending version. On reopening, its temporary file is removed and the outcome becomes interrupted. A complete published file surviving a metadata failure is retained and labelled recovered for manual review. Original media is never deleted during recovery. Disk-full and encoder errors leave the original intact and report failure. If the source changes, reopen it as a new recording before exporting. Do not hand-edit project metadata.

Separate-track capture, reframing, stitching, waveform/transcript editing and replacing cloud versions remain future work. The delivered editing scope is an accurate timed trim with recoverable local export history.
