# Untangle UI/UX overhaul

This stack changes the recorder workspace and local review flow. The user retains merge approval. It is not installed by this thread.

[Watch the before/after comparison](untangle-before-after.mp4). It contains captioned steps from actual Qt widgets, generated by the same inert fixture on both versions. It is not live desktop capture. Capture, audio, encoding, playback and services are mocked. Elapsed time and the saved-file result are injected test events. No user feedback video, private speech transcript or personal screen content is included.

Before is the pushed main revision `39749415a715314bbed51d5ff6194457a6d43115`, which already contains the separately merged feedback fixes. After is this stack. The manifests in `before-review/` and `after/` identify the production source hashes and each observed task.

## Changes to review

1. Graphite/slate base colors, restrained indigo actions, clear selection, and matched light/dark status colors. Existing theme names, settings and branding remain compatible.
2. A persistent bottom bar groups recording time, pause, restart, discard and Stop and save. Recordings and Sharing remain available when setup controls are hidden. The explicit Show/Hide controls button has fixed width and a short fade when controls return.
3. Routine technical details remain collapsed. Recording time stays visible independently. Warnings still show. A camera-layout shortcut reveals the existing shape/size/position controls without changing their behavior.
4. Stable active recording can continue while the user browses the library. Navigation does not release capture audio, reset the portal source or reposition the floating camera. Stop remains available and returns to the recorder for saving. Countdown, preparation and saving keep their navigation guards. Sharing is read-only during a take.
5. Recording names get a full list row above metadata and row actions. Playback and editing are separate from destinations. Library maintenance and Drive options remain reachable through named menus. Long sharing results scroll without displacing playback controls.

The timer belongs to the app interface, not the OBS camera composition. Entire-screen recording can include any visible app window; this change does not promise to exclude Untangle from full-screen capture.

## Evidence and acceptance

The existing isolated suite covers recording/recovery, audio ownership, input locking, files, sharing consent, playback, keyboard focus and geometry. New focused checks cover active-take library navigation, persistent stop/pause/time, frozen paused time, read-only sharing preferences, portal loss while browsing, and menu/long-result reachability.

Each stack layer was checked independently from an immutable source export: palette 697 tests, workspace 702 tests, complete stack 703 tests. All passed with the same three skips. Shell syntax and whitespace checks passed. [Machine-readable validation](validation.json) records tested revisions and application hashes.

The former exact "no engine calls" detail-toggle assertion now permits only display resizing and a mock truth check. It continues to reject every capture/audio operation. Display resizing is required when the workspace changes; it does not alter the recorded canvas.

Two independent visual reviewers compared anonymous full-window packs. Both preferred the new review layout, grouped recording controls and browsing during a take. They preferred the old explicit sidebar label over the first candidate's vague "Controls" label. The final version restores explicit Show/Hide wording at fixed width. These judgments are evidence of agent preference, not human usability measurements or independent cross-provider consensus.

A fresh exploratory agent found and selected the synthetic local walkthrough without playback, then returned to setup. Its four-action trace is under `exploration/`. One initial artifact-path mistake is recorded rather than counted as a UI failure. The second metadata line can still elide; the selected take exposes its full metadata.

The full synthetic render matrix covers 74 captures, including both themes, supported window sizes, camera/screen, canvas shapes, zoom, expanded controls, library, errors and recording states. `matrix-manifest.json` records hashes. Legacy hidden Fit/Fill preferences are set programmatically for composition captures; those images do not claim a visible control. The Settings image captures its actual dialog dimensions. The complete local matrix is generated, not checked in as duplicate images.

Native X11 overlay input is unavailable here because Xvfb is absent. Device-capture and hardware-audio opt-ins stay skipped. No synthetic pass certifies Bluetooth microphone quality, live Wayland/OBS pixels, audible playback, real Loom speed or remote permissions.

## Repeat the loop

Run from the repository root with the pinned project dependencies and working bubblewrap namespaces:

```bash
./scripts/test.sh
bash -n scripts/*.sh bin/*
./scripts/render-safe.sh docs/ux-overhaul/matrix ui
./scripts/render-safe.sh docs/ux-overhaul/after walkthrough --version after
./scripts/render-safe.sh docs/ux-overhaul/exploration session --actions /absolute/path/to/actions.json
python3 scripts/build-ux-video.py --before docs/ux-overhaul/before-review --after docs/ux-overhaul/after --output docs/ux-overhaul/untangle-before-after.mp4
```

An action file must be available in the sandbox's read-only filesystem, not a host `/tmp` path hidden by isolation. The session also accepts JSON lines on stdin and returns screenshot paths, visible/enabled control IDs and an action trace. Its limit is 30 actions or 120 seconds. It cannot execute arbitrary Python or shell commands. Actions go through Qt on its main thread. The controller/model remains outside the device/network sandbox. Only the dedicated evidence output is writable on the host.

For another candidate, freeze the accepted revision and reference pack, choose one user task, let a fresh agent explore through observations, patch one area, run required checks and affected captures, and ask fresh anonymous comparisons. Reject failed/incomplete checks or regressions. Keep rejected rounds locally. Stop at six rounds/two hours after setup, two rounds without gain, disagreement, missing required evidence or usage exhaustion. Use Codex (elhaam), the default service tier and no fast mode. This is an agent-operated loop with reproducible tools, not an unattended background service or recurring schedule.

The initial `ui` renderer had stale hidden theme/disclosure assumptions. The wrapper and renderer now use current production APIs and refuse host device access. The full suite uses its existing mandatory runner. No safety gate was bypassed.

## Ownership and rollback

The view owns layout and the recording-state label; OBS, audio helpers and storage retain their existing responsibilities. Active navigation relies on separating preview-display lifetime from the ongoing capture lifetime. The tests reject audio release, portal reset and scene reconfiguration during that navigation. Unexpected native display/stacking behavior still requires a separately authorized test desktop.

The stack is reversible. Revert the library layer, then the workspace layer, then the palette layer. No settings-key migration, file-format change, destructive data rewrite or default upload/quality change is introduced. Keep the existing local videos and compatibility paths. The baseline revision remains a safe source reference; do not reinstall anything from an uncommitted checkout.
