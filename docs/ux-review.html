2. P2 · Find the active upload from the library

Offer a link back to the active transfer from its library row. Retain existing cancellation confirmation and uncertain-state warning. Test library/back/cancel through transfer and permission checks.

Evidence and risk

app.py:2557–2574 correctly relabels Retry as Cancel upload during active transfer; 2617–2633 confirms cancellation and marks uncertain outcomes. Library navigation remains enabled during upload, while its selected-file actions at recordings.py:409–479 show uploading state without a matching cancel control.

Scope: Upload navigation, medium. Cancellation already exists; this is a discovery proposal, not a missing-cancel bug.

3. P1 · Explain deletion prerequisites earlier

Explain the remote-copy prerequisite before confirmation, with a non-destructive way to archive first. Keep the final fresh verification and file-identity recheck. Test offline, remote missing, changed file and partial batch outcomes.

Evidence and risk

recordings.py:693–719 confirms permanent deletion before 721–772 checks for a current remote copy. Users can approve deletion only to learn that deletion is blocked.

Scope: Deletion flow, medium. Never weaken the existing policy for parity with a competitor.

4. P1 · Show whether Drive scheduling is active

Show separate states for destination saved, archiving enabled, scheduler observed and last verified upload. Link to the other workstream's guide rather than duplicating its wizard. Test missing scheduler/config and stale status.

Evidence and risk

drive_dialog.py:54–64 and 131–138 saves archive enablement but separately states scheduling requires a setup script. Checking the box does not establish that a scheduler is active.

Scope: Archive UI/status integration, medium; no timer activation without authorization.

5. P1 · Review the recording just saved

Offer Review recording for the exact saved file after naming finishes. Keep review silent until Play, preserve recorder choices, and do not auto-upload. Test rename, title failure, discard, missing file and return.

Evidence and risk

app.py:1863–1890 ends a successful save with naming and a generic playback suggestion; the upload panel's Recordings shortcut is separate at 739–740. Local-only users must find the library themselves.

Scope: Navigation/completion flow, medium. Loom's finished preview is a useful reference.

6. P2 · Check the library toolbar at minimum size

Re-render the current library under the safe renderer policy once authorized; if crowded at 960×760, move secondary archive actions to a labelled menu or separate row. Include long filenames and uploaded/error states.

Evidence and risk

recordings.py:259–279 puts Refresh, Open folder, archive review and Google Drive in one horizontal library-tools row; file list minimum width is 230 at line 140. Older screenshots have only two actions.

Scope: Layout/navigation, small to medium; crowding is a source-based concern, not a reproduced current clipping claim.

7. P2 · Summarize inputs before capture

Carry target and selected audio summary into a compact preflight/countdown view. Keep Escape cancellation and do not imply that live signal proves saved speech. Test no-window, camera off, microphone off and delayed readiness.

Evidence and risk

app.py:822–838 already constructs a useful target/output caption, while 1394–1424 shows generic countdown instructions and hides the recorder before capture.

Scope: Capture flow, medium; approval required.

8. P2 · Unify storage and sharing navigation

Agree on one storage/sharing overview that links to both providers and distinguishes local save, archive and audience. Preserve TWG-wide sign-out warning and independent credentials.

Evidence and risk

app.py:2342–2474 groups Loom connection, upload preferences and title options under Sharing. Drive lives in the library at recordings.py:277–279.

Scope: Information architecture/auth navigation, medium. No account operations in this PR.

9. P2 · Show operation-specific Drive progress

Use operation-specific progress and a per-file completion summary with destination and failed items. Keep duplicate-upload warning and avoid promising verified retention for manual uploads. Test partial failure and retry.

Evidence and risk

drive_dialog.py:91–116 uses the same browser-sign-in progress message for every operation and ends successful tasks with Done. Selected upload results are not summarized there.

Scope: Upload feedback, medium.

10. P2 · Show audience status beside the share link

Put audience status and its verification result beside Copy Loom link. Keep copying available with an explicit warning if permission checks failed. Test title failure independently of visibility failure.

Evidence and risk

app.py:2918 and recordings.py:485 distinguish uploaded/processing/uncertain and surface visibility warnings, which is good. Preferences in Sharing are still separate from the finished take.

Scope: Sharing flow, medium; no permission-default change proposed automatically.

11. P2 · Make shortcuts easier to discover

Add a read-only shortcut list in Settings first; separately assess conflict detection/remapping and a visible way to discover bubble controls. Test keyboard focus without desktop speech settings.

Evidence and risk

app.py:772 and tray/bubble menus describe fixed shortcuts. floating.py:368 exposes recording controls through a context menu.

Scope: Discovery is small; key registration/remapping is medium and separate.

12. P3 · Design editing around preserved originals

If post-record layout editing is wanted, design separate tracks/project metadata and versioned exports before adding controls. For simple trims, preserve the source and create a new export. Test disk-full/cancel/version recovery.

Evidence and risk

engine.py:1400–1450 encodes a composed scene; composition.py places camera crops into that output. The library is a player, not a non-destructive editor.

Scope: Capture/storage/editor architecture, large. Supercut's separate-stream model cannot be copied with a label change.
